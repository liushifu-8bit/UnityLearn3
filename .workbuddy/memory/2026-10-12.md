## 深挖：本地 .git 处于半损坏状态

按严重度排序的真正拦路虎：
1. **`.git/index.lock` 残留**（2026-10-12 18:51:13 创建，0 字节）→ 任何 `git add` 直接报
   `fatal: Unable to create '.../.git/index.lock': File exists`，**根本提交不了**。
2. 本地 `main` 分支 0 个提交、暂存区为空 → `git push` 必然报 `src refspec main does not match any`。
3. `.git/objects/pack/` 残留 3 个中断的临时包：
   `.tmp-32540-pack-8a68696b63d0b0c7769efaef38eb0ee4e2ebedf3.{idx,pack,rev}`。
4. `.git/1.txt`（内容 "1"，3 字节）垃圾文件；`.git` 下**没有 index 文件**，
   但 objects 里有 **12929 个松散对象** → 之前某次大规模 `git add` 被中途掐断。
5. **TortoiseGit 后台进程在跑**：`TGitCache`(PID 14668) + `TortoiseGitProc`(PID 5232)
   —— 这是 .git 锁文件残留 / ref 写入异常的常见元凶。
6. 未解异常（两个不同 git 二进制均可复现，非单一安装问题）：
   `git update-ref` 到 `refs/remotes/*`（如 origin/main、foo/bar）**静默返回 0 但不落盘**；
   而 `refs/heads/testbranch`、`refs/tags/v1` **写入正常**。
   已排除：ACL/属性一致、PowerShell 直接往 `refs/remotes/origin/` 写文件成功、
   磁盘 NTFS 剩余 105GB、无 hosts 干扰、无 GIT_DIR 环境变量。
   怀疑是外部进程（TGitCache/杀软）清理 `refs/remotes/` 空目录。
   → 表现为本地长期缺少 origin/main 跟踪信息；不影响 push 到远端本身。
